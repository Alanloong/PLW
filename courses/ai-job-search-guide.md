### 这个项目是干什么的？

想象你在找工作。正常情况下你要：
1. 去招聘网站搜职位
2. 一个个看职位描述
3. 针对每个职位改简历
4. 写求职信
5. 提交申请

这个项目用 AI 帮你自动完成第2-4步。你给它一个职位链接，它会：
- 读取职位描述
- 判断你合不合适
- 写一份定制的简历和求职信
- 生成 PDF 直接可用

### 谁做的？为什么做？

作者 Mads Lorentzen 是一名地球物理学家，2025年底被裁了。他没有手动海投简历，而是花了三个月做了这个 AI 工具。结果是：**69 份申请 → 20 场面试 → 1 份录用通知。**

他把这个项目开源了，任何人都可以用。

### 这跟普通软件有什么不同？

普通软件是用编程语言写的（Java、Python等）。这个项目大部分是 **Markdown 文件**（纯文本文档），用来告诉 AI 该怎么做。

```
普通软件：代码 → 电脑执行
这个项目：说明书 → AI 阅读并执行
```

### 什么是 Agent（智能体）？

**Agent** 就是"能自己动脑干活的 AI"，不是普通的问答机器人。

| 类型 | 能力 | 例子 |
|------|------|------|
| 普通聊天AI | 你问一句它答一句 | "帮我写首诗" → 写完就停 |
| **Agent** | 能自己计划、执行、检查 | "帮我申请工作" → 它自己分析职位→写简历→编译PDF→检查排版→给你 |

**区别：**

```
普通 AI：
你说话 → AI 回答 → 结束

Agent：
你下命令 → AI 自己规划步骤 → 一步步执行 → 
过程中自己判断 → 遇到问题自己解决 → 检查成果 → 汇报结果
```

### 这个项目里有几种 Agent

1. **单个 AI 干活** — 比如 `/setup` 命令，一个 AI 从头做到尾
2. **两个 AI 配合** — 比如 `/apply` 命令，一个写简历、另一个审查挑毛病
3. **AI 调用工具** — 比如 `/scrape` 命令，AI 调用爬虫程序去搜职位

### 什么是"说明书模式"？

这个项目最核心的设计思路就是**用 Markdown 文件写说明书，指挥 AI 干活**。

每个 `.md` 文件都不是给人类看的文档，而是给 AI 读的操作指引。

**三种说明书：**

```
第一类：角色说明书（CLAUDE.md）
  告诉AI：你是谁、你会什么
  
第二类：命令说明书（.claude/commands/*.md）
  告诉AI：当用户说"/apply"时，按以下步骤执行
  
第三类：技能说明书（.claude/skills/*/*.md）
  告诉AI：你的简历长什么样、怎么判断工作好坏
```

### 三层架构

这个项目的文件分三层：

```
┌─────────────────┐
│   命令层         │  ← 你直接用的（/setup、/scrape、/apply）
│   commands/     │     告诉AI按什么步骤做
├─────────────────┤
│   技能层         │  ← AI 的知识库
│   skills/       │     告诉AI你的档案、评估标准
├─────────────────┤
│   工具层         │  ← 真正的代码（爬虫）
│   agents/skills/ │     AI 调用它们搜职位
└─────────────────┘
```

### 举个实际例子

当你输入 `/apply https://xxx` 时：

```
你：发了一个职位链接

第1步：AI 读"命令说明书"（apply.md）
       → 知道要按 6 步走
       
第2步：AI 读"技能说明书"
       → 知道你是谁（01-candidate-profile.md）
       → 知道怎么判断合不合适（04-job-evaluation.md）
       
第3步：AI 开始干活
       → 分析职位 → 写简历 → 启动另一个AI审查 → 修改 → 编译PDF
```

整个过程就像经理（你）跟实习生（AI）说："去翻操作手册第5页，按步骤来。"

### 核心要点

你不需要会编程，只需要学会**两件事**：
1. 知道每个 .md 文件是告诉 AI 什么的
2. 能看懂命令文件里的步骤

| 项目 | 内容 |

### 为什么需要一个AI不够？

让一个 AI 直接写简历会有什么问题？

- 它可能漏掉职位描述里的关键要求
- 它可能写得很空泛，不针对这家公司
- 它自己检查自己的成果，往往看不出毛病（就像自己写的作文自己难挑错）

这个项目用了一个很聪明的办法：**用两个 AI，一个写、一个审。**

### 双AI协作流程图

```
你：发来一个职位链接
         │
         ▼
┌────────────────────────────┐
│ AI 1号：起草者              │
│                            │
│ 1. 分析职位要求             │
│ 2. 评估匹配度               │
│ 3. 写简历 + 求职信          │
└──────────┬─────────────────┘
           │
           ▼
┌────────────────────────────┐
│ AI 2号：审查者              │
│（全新启动，没看过前面的内容）  │
│                            │
│ 1. 自己去调研这家公司        │
│ 2. 挑简历的毛病             │
│ 3. 挑求职信的毛病           │
│ 4. 给出修改建议             │
└──────────┬─────────────────┘
           │
           ▼
┌────────────────────────────┐
│ AI 1号：修改                │
│                            │
│ 根据审查意见修改文件         │
└──────────┬─────────────────┘
           │
           ▼
┌────────────────────────────┐
│ 编译PDF + 检查排版          │
│ 检查ATS扫描效果             │
└──────────┬─────────────────┘
           │
           ▼
     你：拿到最终文件
```

### 为什么 AI 2 号要"全新启动"？

这点很关键。AI 2 号在启动时**没有看过 AI 1 号写了什么**，它拿了原始的职位描述和简历草稿，自己去判断。

这就像：
- AI 1 号写了一份简历 → AI 2 号以招聘经理的视角来看 → 挑出真正的问题

如果让 AI 2 号知道 AI 1 号是怎么想的，它就很难挑出毛病了——它会顺着前面的思路走。

### 审查者具体查什么？

AI 2 号拿到简历和求职信后，会做这几件事：

**1. 调研公司**
- 去搜这家公司的官网、产品、新闻
- 了解这家公司的业务方向

**2. 事实核对**
- 简历里的每个日期、职位、数据都要跟原始档案对一遍
- 防止 AI 1 号编造经历

**3. 内容审查**
- 有没有漏掉职位要求里的关键词？
- 表述够不够有力？
- 语气是否符合你的性格特点？

**4. 给出修改建议**
- 直接给出要替换的文本（AI 1 号可以直接照搬修改）

### 检查PDF

改完之后还要编译成 PDF，AI 会"看一看"生成的页面：

- 简历**必须正好2页**，不能多不能少
- 求职信**必须正好1页**
- 标题不能孤零零地留在页面底部
- 字体要一致
- 还要检查 PDF 的文字层——招聘系统（ATS）扫描时能不能正常读取

如果排版有问题，AI 会自动调整，重新编译，直到满意为止。

### 这个模式你能用在哪？

**双AI协作模式可以套用到很多场景：**

| 场景 | AI 1 号 | AI 2 号 |
|------|---------|---------|
| 写方案 | 写初稿 | 挑逻辑漏洞 |
| 写代码 | 写代码 | Code Review |
| 写文章 | 写文章 | 检查错别字和逻辑 |
| 做PPT | 做内容 | 检查排版和一致性 |

### 核心要点

这个项目的真正价值不是"AI 写简历"——那是表面功能。

**真正的价值是这个模式：把复杂任务拆成多步，让多个 AI 各司其职，互相检查。**
