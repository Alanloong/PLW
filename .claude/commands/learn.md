# /learn - PLW 项目学习工作流

当你收到 `/learn <GitHub URL>` 命令时，启动一套标准化的项目学习工作流。该工作流包含5个阶段，按顺序执行。

**目标：** 先了解项目，再了解用户，然后生成定制课程，逐课推进学习。

---

## 核心原则

1. **用户编程基础薄弱** — 所有讲解用大白话，拆解步骤，不要默认用户懂任何编程知识
2. **全程中文沟通**
3. **不私自做决定** — 遇到多种选择时，列出选项让用户选
4. **进度自动推进** — 用户学完一课，自动准备下一课，不需要用户来提醒

---

## 第0步：解析参数与定位项目

### 0a. 解析 GitHub URL

从 `$ARGUMENTS` 中提取 GitHub 项目的 URL。支持的格式：
- `https://github.com/用户名/项目名`
- `https://github.com/用户名/项目名/tree/分支`
- 直接跟项目名（如 `ai-job-search`）

### 0b. 提取项目名

从 URL 中提取项目名（最后一个路径段，去掉分支信息等）。

### 0c. 在 repos/ 目录中查找项目文件夹

```
场景A：找到 repos/项目名-master/ → 使用它
场景B：找到 repos/项目名/ → 使用它
场景C：找到了多个匹配的 → 让用户选
场景D：没有找到 → 提示用户
```

如果没有找到，向用户说明：
> 请将下载的 GitHub 项目 zip 解压到 `repos/` 文件夹中，文件夹名应为 `[项目名]-master/`。
> 再次输入 `/learn <URL>` 继续。

### 0d. 确认项目信息

向用户展示找到的项目信息（项目名、路径、文件数量），确认无误后继续。

---

## 第1阶段：项目分析

目标：全面了解项目，输出分析报告。

### 1a. deepwiki 速览

将 URL 中的 `github.com` 替换为 `deepwiki.com`，用 WebFetch 获取项目深度分析。

如果 deepwiki 访问失败，改用 WebSearch 搜索项目分析。

### 1b. 本地文件深入阅读

进入 `repos/[项目名]-master/`，按从大到小的顺序深入遍历文件：

**第一轮：项目骨架（根目录关键文件）**
- `README.md` — 项目简介、功能、使用方法
- `CLAUDE.md` — 如果存在，读取角色设定
- `AGENTS.md` — Agent 指南
- `SETUP.md` — 安装说明
- `package.json` / `pyproject.toml` — 技术栈
- `LICENSE` — 许可证

**第二轮：核心代码/配置目录**
- `.claude/` 目录（如果有的话）
- `.claude/commands/` — 命令文件
- `.claude/skills/` — 技能文件
- `src/` 或 `cli/` 目录（真正的代码目录）

**第三轮：其他目录**
- 模板文件、文档、测试、工具等

**阅读策略：**
- 每个文件先读开头30行了解结构，再根据重要性决定是否通读
- 遇到明显是配置/模板的文件，只了解作用，不深入内容
- 遇到核心逻辑文件，仔细阅读

### 1c. 输出项目分析报告

向用户呈现项目分析报告，格式如下：

```
## 📋 项目分析报告：[项目名]

### 一句话概括
[用一句话说清楚这个项目是干什么的]

### 技术栈
- 语言：[Python/TypeScript/Go等]
- 框架/工具：[列出核心依赖]
- 运行环境：[Node.js/Python/Bun等]

### 核心架构
[简述项目的三层/四层架构，核心设计模式]

### 关键文件速览
| 文件/目录 | 作用 | 重要度 |
|-----------|------|--------|
| xxx | xxx | ★★★★★ |
| xxx | xxx | ★★★ |

### 这个项目教会你什么
[学完这个项目你能理解什么核心概念]

### 学习建议
[基于项目特点，给出学习重点建议]
```

---

## 第2阶段：了解用户

目标：通过对话了解用户的知识基础和学习需求，为定制课程做准备。

### 2a. 确认学习场景

向用户展示三个学习场景，让用户选择：

> 你想怎么学这个项目？选一个最适合你的：
>
> **① 快速上手** — 了解项目是干什么的，能快速用起来就行
>   适合：想用这个项目，不需要深入了解原理
>
> **② 学习原理** — 搞懂项目的设计思路和核心原理，能借鉴到自己项目中
>   适合：想学习好的设计模式，用到自己的开发中
>
> **③ 掌握代码** — 从代码层面深入理解，逐文件学习
>   适合：想认真学习项目源码，提升编程能力

用户选择后确认。

### 2b. 了解编程基础

用对话的方式了解用户的编程基础。提问时结合项目涉及的技术来问，这样能判断用户对项目中用到的技术熟不熟。

**提问示例（根据项目技术栈调整）：**
- "你的编程基础怎么样？零基础 / 入门不久 / 有一定经验？"
- "你之前听说过 [项目中用到的技术，比如 Claude Code / Agent] 吗？"
- "你平时写代码吗？主要用什么语言？"
- "你自己有没有做过什么项目？"

### 2c. 了解学习安排

- "你计划每天花多少时间学习？30分钟？1小时？"
- "你有什么时间限制吗？（比如这周内想学完）"

### 2d. 汇总用户画像

将了解到的用户信息整理成用户画像，向用户确认：

```
## 用户画像

### 学习场景
[快速上手 / 学习原理 / 掌握代码]

### 编程基础
[零基础 / 入门 / 有经验]

### 技术熟悉度
- [技术A]：[熟悉程度]
- [技术B]：[熟悉程度]

### 学习安排
- 每天：[X] 分钟
- 完成期限：[灵活 / X天内]
- 特别需求：[用户提到的其他需求]

---

以上信息对吗？我根据这个来给你定制课程。
```

用户确认后进入下一阶段。

---

## 第3阶段：生成课程大纲

目标：根据项目分析和用户画像，生成定制的课程大纲。

### 3a. 基于项目+用户定制大纲

根据项目特点和用户的学习场景、基础水平，定制课程大纲。

**大纲结构参考（根据实际情况调整）：**

```
模块一：认知建立
- 第1课：[项目初识] — 项目是干什么的
- 第2课：[核心概念] — 搞懂关键术语

模块二：结构认知
- 第3课：[目录结构] — 文件都是干嘛的
- 第4课：[核心文件] — 精读最重要的文件

模块三：深入理解
- 第5课：[核心机制一] — [具体内容]
- 第6课：[核心机制二] — [具体内容]

模块四：总结实践
- 第7课：[总结与实战] — 学以致用
```

**不同学习场景的课程调整：**
- 快速上手：偏重概念和用法，减少技术细节
- 学习原理：增加设计模式、架构分析
- 掌握代码：增加代码走读、关键文件精讲

### 3b. 写入学习指南文件

将大纲写入 `courses/[项目名]学习指南.md`。

文件结构：
```markdown
# [项目名] 学习指南

## 项目分析
[来自第1阶段的报告]

## 用户画像
[来自第2阶段的画像]

## 课程大纲
[完整大纲]

---

<!-- 以下内容逐课填充 -->

## 第1课：[课程名]
<!-- 随着学习推进逐步填充 -->

## 第2课：[课程名]
<!-- ... -->
```

### 3c. 创建进度文件

创建 `progress.json`：

```json
{
  "project": {
    "name": "项目名",
    "url": "GitHub URL",
    "learnScenario": "快速上手/学习原理/掌握代码"
  },
  "course": {
    "totalLessons": 7,
    "currentLesson": 0,
    "completedLessons": [],
    "currentLessonTitle": ""
  },
  "user": {
    "skillLevel": "零基础/入门/有经验",
    "dailyMinutes": 30,
    "notes": ""
  }
}
```

### 3d. 更新 CLAUDE.md

将课程大纲和学习进度写入 CLAUDE.md。

---

## 第4阶段：逐课填充与推进

目标：逐课生成详细内容，用户学完一课自动推进下一课。

### 4a. 填充第1课

根据大纲，写出第1课的完整内容，追加到 `courses/[项目名]学习指南.md` 中。

每课结构：
```markdown
### 第X课：[课程名]

| 项目 | 内容 |
|------|------|
| **学习目标** | 学完这节课你能掌握什么 |
| **学习内容** | 要读哪些文件、理解哪些概念 |
| **重点文件** | 这一课涉及的文件清单 |
| **课后任务** | 动手做的小任务 |

#### 课程正文

[这里写课程的具体内容...]

---

#### 课后任务
[具体任务说明]

**完成标准：** [怎么样算学会了]
```

### 4b. 更新进度

完成一课填充后：
1. 更新 `progress.json`（currentLesson +1，添加到 completedLessons）
2. 同步更新 `CLAUDE.md`

### 4c. 通知用户学习

> 📖 第1课：[课程名] 已经准备好了！
> 打开 `courses/[项目名]学习指南.md` 就可以开始学习。
> 学完之后告诉我一声，我来给你准备下一课。

### 4d. 等待用户完成，推进下一课

用户告知学完后：

1. **暗中观察**：回顾这次对话，默默记录以下信息（不要告诉用户你在记）：
   - 用户有没有额外问问题？问了什么？
   - 用户有没有说"看不懂"、"再多讲讲"之类的话？
   - 用户有没有提到自己的背景、经历、偏好？
   - 用户是不是直接说"下一课"而不是问问题？

   这些观察临时记在脑子里就行，不需要写入文件。

2. 根据观察调整下一课的难度/深度
3. 填充下一课内容
4. 更新进度
5. 循环直到课程全部完成

### 4e. 课程完成 — 双AI个性化优化

所有课程完成后，启动双AI流程：

**AI 1 号（观察者）：** 回顾整个学习过程中的所有观察，整理成"用户个性化特征报告"。

**AI 2 号（分析者）：** 使用 Agent 工具启动一个 `general-purpose` 子Agent，把观察报告传给它：

> 你是一位学习行为分析师。分析以下用户在学习过程中表现出的个性化特征，提出课程优化建议。
>
> 观察记录：
> [粘贴AI 1号的观察报告]
>
> 输出 JSON：
> ```json
> {
>   "userTraits": "用户学习特点总结",
>   "templateOptimizations": [
>     {"file": "模板文件名", "change": "具体修改建议"}
>   ]
> }
> ```

拿到 AI 2 号的分析后，**不要直接改文件**，而是向用户展示并请求确认：

> 课程全部完成了！在学习过程中，我注意到你的一些学习特点：
>
> [展示用户特征，例如：你对XX内容特别感兴趣、你更喜欢XX风格等]
>
> 基于这些观察，我可以优化课程模板，让下次生成课程更适合你。优化计划：
> [展示具体优化内容]
>
> 是否应用这些优化？

### 4f. 应用优化

- 用户确认 → 修改模板文件，更新 `feedback.json` 存档
- 用户拒绝 → 仅记录到 `feedback.json`，不做修改

最后更新进度和 CLAUDE.md。

---

## 附带规则

### 进度自动推进机制
- 用户学完一课告知你后，**自动开始准备下一课**，不需要用户说"下一课"
- 如果用户超过24小时没动静，主动询问学习进度
- 每次课程更新时，同步更新 `progress.json` 和 `CLAUDE.md`

### 关于progress.json 的格式说明

```json
{
  "project": {
    "name": "项目名",
    "url": "GitHub地址",
    "learnScenario": "学习场景"
  },
  "course": {
    "totalLessons": 7,
    "currentLesson": 1,
    "completedLessons": [1],
    "currentLessonTitle": "当前课程标题"
  },
  "user": {
    "skillLevel": "入门",
    "dailyMinutes": 30
  },
  "updatedAt": "2026-07-28T13:00:00"
}
```
